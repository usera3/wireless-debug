# 浏览器串口直连

本地串口模式通过 `navigator.serial` 直接传输二进制数据，无本地串口 HTTP/WebSocket
服务。设备控制台入口是 `/index.html`，根路径 `/` 是云平台入口。ESP32 和云端网络
模式继续使用原有 HTTP/WebSocket 服务；“无需后端”指本地浏览器串口路径。
COM、CDC 或 USB-UART 串口设备使用本地串口模式；ESP32 USB NCM 虚拟网卡提供的是
网络接口，仍通过原有 HTTP/WebSocket 地址连接，不会出现在串口设备选择器中。

## 使用条件与权限

- 使用提供 Web Serial API 的桌面浏览器，例如桌面 Chrome / Edge。开发者工具中可检查
  `window.isSecureContext` 和 `'serial' in navigator`；未提供 API 时界面会说明原因。
- 页面必须由 HTTPS 或浏览器认可的可信 localhost 来源提供。普通局域网 HTTP 地址
  （例如另一台电脑的 IP）可能不满足安全上下文要求；直接打开本地 HTML 文件不是本项目
  的支持部署方式。
- 请先用独立桌面浏览器打开页面。IDE 内嵌浏览器或第三方 iframe 预览可能未提供 API，
  或被宿主权限策略限制。在当前站点点击“选择并授权串口”，浏览器才会弹出设备选择器。
  如需 iframe 部署，宿主需配置允许 serial 的 Permissions Policy 和 iframe 权限；
  策略拒绝时检查站点与宿主配置。
- 列表只包含当前站点已授权且可用的端口；“刷新串口”不会弹出选择器、申请新权限或
  枚举系统全部 COM 端口。授权与站点来源相关，换域名/端口可能需要重新授权。
- 页面使用内存中的设备身份与 VID/PID（可用时）显示列表，不保证能显示 Windows COM
  名称或区分所有同型号设备。即使是同一硬件，拔插后浏览器也可能返回新端口对象，必须
  人工核对后连接；VID/PID 是型号信息，不是唯一身份。旧备注不会附到新对象上。
- 系统仍需安装 USB 转串口驱动，并关闭占用设备的终端、调试器和旧串口代理。选中实际
  浏览器所在电脑上的 USB 串口；WSL 内的 Node/Python 不参与最终串口通信。

## 连接、采样与烧录

进入“连接设置 → 本地串口”，授权或选择已授权设备，确认波特率，然后点击“连接串口”。
默认 2000000 baud、8 数据位、无校验、1 停止位、无流控（8N1）。可输入整数
1200..5000000，实际可用速率取决于驱动与设备。连接、连接中或等待自动重连时不能更改波特率；先断开或取消自动重连，
再修改并手动连接。“串口身份待确认”时允许选择端口和波特率，但必须点击确认才打开。
烧录时不能手动断开或切换连接，意外链路丢失仍会中止正在等待的操作。

“串口传输已连接”仅表示端口已打开。下位机必须支持项目协议，并使用匹配的波特率、
接线、电平和供电，参数读回或有效采样才能证明下位机响应。串口模式可加载本地 Excel、
使用参数/地址示波器与下位机烧录；不显示 ESP32 Wi-Fi/BLE/设备参数文件控制。

串口拔出、读写异常或流结束会取消当前连接代次的待处理请求、停止采样/心跳并释放资源。
仅当本页曾成功手动连接的同一浏览器端口对象重新出现后，才按原波特率自动恢复连接，
不再弹出授权窗口或要求重新选择。恢复只重开字节传输，采样、心跳、旧命令和烧录不会自动继续。
等待时显示“等待串口重新接入”，可点击“取消自动重连”。切到其他功能页仍会等待恢复。

恢复使用浏览器返回的同一个 `SerialPort` 对象，不会仅凭相同 VID/PID 打开另一台同型号
设备。如果原对象不在列表、出现其他已授权端口，显示“串口身份待确认”，解锁列表，
但不自动选中或打开任何新对象。核对设备后，选择端口并点击“确认所选串口并连接”；
已授权端口不会因此再次弹出授权窗。无法区分时可主动点击“选择并授权串口”，在浏览器
弹窗中核对系统名称。等待确认时原对象若恢复，仍可自动重连；可点击“取消自动重连”停止等待。
刷新整个网页、权限失效、主动断开、切换连接目标或串口释放失败后，需要手动连接。
每次同一端口对象出现后等待 600 ms，再尝试打开；临时打开失败最多尝试
三次，间隔 1000 ms，失败后停止。首次发现设备或首次打开失败不会启用自动重连。

烧录过程中掉线始终需要手动重连和检查，不要将中断的烧录当作完成；重新检查固件和目标，
再显式开始新的操作。如果提示释放失败，不应把界面“未打开”当作底层资源已释放的证明，
需先排除驱动占用或设备异常。Windows 显示“无法识别的 USB 设备”时没有可打开的串口，
前端无法代替系统枚举；如需 BOOT/RESET 才恢复，必须单独记录，不能算作正常上电拔插通过。

## 静态部署与开发工具

已有依赖环境中执行 `npm run build:web` 生成 `dist/`，
将整个目录交给静态站点托管。
服务器需正确提供 JavaScript/CSS MIME 类型，保留 `/index.html` 设备入口与 `/` 云平台
入口的区别；不要把设备入口改写成云平台页面。生产本地串口页面使用 HTTPS；开发可用
`npm run dev -- --host 127.0.0.1 --port 5679`，或构建后
`npm run preview -- --host 127.0.0.1 --port 5680`。

Node、Vite、preview 和测试脚本中的静态 HTTP 服务都只是开发/验收工具。最终用户通过
静态网页连接串口，不需要在自己的电脑上启动 Python/Node 串口后端。
`npm run build:firmware-assets` 还包含固件资源同步，
不是本说明的静态站点构建步骤。

完全离线交付需要将所有网页资源与本机静态页面启动方式一起封装。
Windows 免安装启动包尚未制作或验收，本分支不承诺直接双击 HTML 即可运行。

## 可重复的软件验收

保持 Vite 在默认 `http://127.0.0.1:5679/index.html` 运行后执行：

```bash
npm run test:browser-serial-transport
npm run test:browser-serial-store
npm run test:browser-serial-reconnect
npm run test:browser-serial-ui
npm run test:browser-serial-acceptance
# 聚合入口还检查源码边界和通用设备能力：npm run test:browser-serial
```

`WEB_URL` 可覆盖源码浏览器验收地址。测试优先使用 `PLAYWRIGHT_MODULE`
指定的外部 Playwright 模块；未设置时尝试解析 `playwright` 包，不依赖开发者个人路径。
例如在 Bash 环境中将测试工具安装到相邻目录，不改变应用依赖：

```bash
npm install --prefix ../web-test-tools --no-save playwright
../web-test-tools/node_modules/.bin/playwright install chromium
export PLAYWRIGHT_MODULE="$(cd ../web-test-tools && pwd)/node_modules/playwright/index.mjs"
npm run test:browser-serial
```

Windows PowerShell 可将 `$env:PLAYWRIGHT_MODULE` 设置为该 `index.mjs` 文件的绝对路径。
构建后运行 `npm run test:browser-serial-static`：它只启动
一个临时静态文件服务器，加载实际 `dist` 资源，完成后自动关闭；不需要 Vite 或串口代理。

串口边界测试替换 `navigator.serial` 与 OS 端口，使用浏览器原生 ReadableStream /
WritableStream。验收使用实际 UI、单例协议路由、取消信号、示波历史和图表：已知数据以
任意切块进入 readable，CSV 验证四通道各 300 点精确值，并检查画布四条曲线；16 字节
运行时固件验证短 Bootloader 事务的地址、数据与完整命令顺序。拔出/写失败测试检查
锁释放、同对象自动恢复、新对象必须确认、取消恢复、采样停止与烧录中断后仍需手动重连且不续传。
串口所有页面的业务 API/应用 WebSocket
尝试计数必须为 0。开发 HMR WebSocket 不属于串口业务；静态验收不允许任何 WebSocket。

这些结果仅证明软件边界模拟通过，不证明真实 USB、电气链路、MCU Flash、掉电恢复或
操作系统驱动时序通过。虚拟 COM 试验也不能替代真实下位机的物理验证。

## USB 拔插人工复验

此步骤需要操作人确认明确目标设备，记录 USB 身份、系统端口、驱动、浏览器版本、
页面来源与波特率，并确保没有其他程序占用。避免选择其他调试设备；先不进行烧录。

1. 打开 `/index.html`，确认没有授权弹窗或自动打开。点击授权，选择目标并手动连接。
   读回一个安全参数或开始已知地址采样，记录响应/曲线和预期数据。
2. 采样中拔出该目标，确认连接断开、停止采样并显示可操作的错误。没有数据时不要仅凭
   “端口已打开”判定通过。若提示释放失败，记录原文并排除驱动/占用问题。
3. 重新插入同一设备，确认系统正常识别：浏览器保留原对象时应自动恢复已连接；返回新
   对象时应显示“串口身份待确认”，不能自动打开。核对后选择新端口并点击确认，记录
   这是人工确认恢复而非自动重连。确认没有继续采样或重发旧请求；显式开始新的采样，
   并核对读回值。系统枚举失败或需要 BOOT/RESET 时另记实际条件，不算正常上电拔插成功。
4. 用另一台已确认身份的同型号设备替换，确认界面不会静默切换或自动连接。手动选择
   正确设备后复验。主动断开或在等待时取消自动重连，确认之后重插不会自动打开，且可
   再次手动连接；身份待确认时可调整波特率，自动打开过程中不能修改。
5. 烧录中断属于单独的有写入操作测试：仅在操作人明确批准固件、目标与恢复方式后执行。
   检查拔出后烧录失败、活动锁退出且重插不续传；重连后先核实目标状态，再显式开始新
   操作。本次自动化验收没有对真实 MCU 进行此步骤。

## 源码边界

本分支从网络版基线整理，不包含已冻结的本地 Python 代理实现或其提交历史。
`npm run test:browser-serial-boundary` 检查代理专用文件、命令和个人机器测试路径没有混入。
既有云端／ESP32 网络功能仍使用 HTTP 与 WebSocket，不属于本地串口代理。
