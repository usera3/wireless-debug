# 云端地址示波器快速启动与平滑刷新设计

## 问题

纯云模式点击“开始”后，前端串行等待停止、三次能力查询和每个通道配置 ACK。公网单次往返约 1.5 至 3.7 秒，四通道实测从点击到运行约 15.8 秒。运行后云服务按 4096 字节、40 毫秒分片，真实数据连续但浏览器更新颗粒仍偏大。

## 设计

1. 以通信目标为键保存最近一次成功读取的 `frameLen`、`maxChannels` 和 `sampleRate`。
2. 局域网模式保持现有严格握手。
3. 云端存在有效缓存时，发送停止命令后立即应用缓存能力；通道配置按顺序连续发送，不等待每个 ACK，随后发送开始命令。
4. 云端无缓存时保留严格能力查询；成功后写入缓存，因此同一设备第二次启动进入快速路径。
5. 示波帧处理器必须在发送开始命令前注册，避免丢失首批波形。
6. 云服务浏览器输出调整为 2048 字节、20 毫秒分片。理论吞吐上限与 4096 字节、40 毫秒相同，但交付频率提高一倍。

## 约束

- 不插值、不生成模拟点、不改变真实时间轴。
- 缓存按设备/通信目标隔离，不能跨设备复用。
- 缓存格式带版本和合理值校验；无效缓存必须回退到严格握手。
- 停止、心跳和错误处理行为保持兼容。
- 本地直连启动路径不得退化。

## 验收

- 已缓存云设备点击开始后目标 2 秒内进入运行并开始收图。
- 首次无缓存仍能正确查询并启动。
- 75 秒纯云测试无断流、无连续 5 秒零帧。
- 浏览器 WebSocket 消息交付频率高于修改前，数据总量和真实时间轴保持一致。
